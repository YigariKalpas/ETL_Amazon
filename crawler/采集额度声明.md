# 采集额度声明（默认许可）

> 本文声明本项目对 Amazon 产品页的**访问额度与限速约定**。
> 参数即代码默认值，改参数等同于改额度，须提交并记入报告。

## 一、默认额度

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--concurrency` | **2**（上限 8） | 工作线程数；只重叠网络等待，不提升请求频率 |
| `--delay` | **3.0 s** | **任意两次请求**之间的最小间隔（全局，与线程数无关） |
| `--jitter` | **0.8 s** | 在最小间隔上叠加的随机抖动 |
| **聚合速率** | **≤ 0.33 req/s** | = 1 / (delay) |
| `--max-attempts` | **3** | 单 ASIN 最多尝试次数 |
| 退避封顶 | **30 s** | 指数退避上限 |
| `--limit` | **100 / 轮** | 单轮采集上限，便于分批观察与中断 |
| robots.txt | **强制遵守**，取不到即中止 | `--ignore-robots` 仅调试，属不合规 |
| IP 轮换 / 代理池 | **不实现** | 作业 §四任务2 禁止以绕过封禁为手段 |

## 二、实测基准（2026-10，100 条）

```
目标 100 个 -> 378 s（含重试约 118 次请求）
成功 87 / 100，restricted = 0，validation_page = 0
```

推算：

| 规模 | 预计耗时 |
|---|---|
| 1,000 条 | ≈ 1.05 小时 |
| 10,000 条 | ≈ 10.5 小时 |
| 253,059 条（全量） | **≈ 11.1 天** |

## 三、额度使用策略（默认）

1. **分批**：每轮 100 条，跑完看统计再决定下一轮；
2. **优先级**：先采评论数多的商品（长尾分布下少量商品覆盖大部分评论）；
3. **分通道统计**：实时采集 / 离线快照 / 第三方数据三条通道的分子分母**分别统计**，
   不得混为同一成功率（作业 §十一 要求）；
4. **受限即记录**：`restricted` / `validation_page` 如实入库，作为"客观不可访问"的证据；
5. **额度变更**：修改 `--delay`/`--concurrency`/`--limit` 即改变额度，应在报告中说明变更理由与时间。

## 四、合规红线（不可调）

- 不得登录、绕过验证码、伪造 UA 或使用 IP 轮换规避封禁；
- 不得在 robots.txt 禁止的路径上采集；
- 不得伪造采集成功率或用空记录冒充成功；
- 采集时间与评论历史时间必须分别记录。
