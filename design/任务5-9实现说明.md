## 一、任务5 人物姓名归一与消歧

脚本：crawler/person_entities.py　产物：data/staging/persons/

| 指标 | 值 |
|---|---|
| 不同人名（规范化后） | 1,388 |
| person 实体 | 1,388 |
| 别名记录 | 1,389 |
| movie_person 关系 | 1,382（角色=actor/director，保留页面顺序） |
| 同名/缩写候选（待复核） | 4 |

策略（保守优先）：

1. 只合并**规范化全名完全相同**者，状态标 auto_same_name、置信度 0.5，可被人工推翻；
2. 仅中间名缩写不同（J. Smith vs John Smith）→ 只生成候选进 same_name_review.csv，**不合并**；
3. 无外部人物 ID，因此不做跨语言/音译合并——符合「姓名相同不代表同一人」的要求；
4. 原始姓名全部保留在 person_alias，规范姓名另存。

## 二、任务6 上映信息补全

脚本：crawler/release_dates.py　产物：data/staging/release_dates/

| 状态 | 数量 | 说明 |
|---|---|---|
| verified（外部源） | **0** | 尚无 IMDb/豆瓣数据，模板已生成 data/external/release_dates.csv |
| inferred（评论上界） | 967 | earliest_review_time 作为「上映不晚于该时间」的条件性上界 |
| missing | 0 | 当前每个 movie 都有评论可用 |

关键约束落地：

- 只有年份时存 release_year + precision=year，不补 1 月 1 日；
- 商品发售日（页面 Release date）**不**当上映年，留在版本层；
- inferred 值单独存 status=inferred 与 condition 说明，永不覆盖 verified。

## 三、任务7 来源冲突处理

脚本：crawler/field_conflicts.py　产物：data/staging/conflicts/

| 指标 | 值 |
|---|---|
| 字段选择记录 | 1,934（canonical_title 967 + release_year 967） |
| release_year 取值状态 | 全部 inferred_only（无 verified 来源） |
| 检测到的冲突 | 0（当前每个字段只有单一来源） |

规则是显式的：优先 verified 外部源 > inferred 上界 > missing；两个 verified 且值冲突时置 status=conflict 不选值。
机制已就绪，等外部数据进来即可产出真实冲突案例。

## 五、任务9 字段级血缘

脚本：crawler/build_field_assertions.py　产物：data/staging/lineage/

| 指标 | 值 |
|---|---|
| 字段断言 | 9,644 |
| 覆盖 movie | 967 |
| 最终选择记录 | 1,934 |

每条断言包含：entity_type、entity_id、field_name、raw_value、normalized_value、source_record_id、
locator（快照哈希 + JSON 路径，如 `sha256#$.studio`）、rule_id、run_id、confidence、created_at。

release_year 目前**没有生成断言**（无可信来源），在 field_selection 里显式记 status=missing/inferred_only，
而不是编造一个值——这正是作业「查不到保留缺失」的要求。

4. 实体层（972 版本）基于 1,054 个已解析页面，而采集已到 1,300+，需要重跑 parse→classify→entities 才能刷新。
