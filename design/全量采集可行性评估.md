# 全量采集可行性评估（启动持续爬取 → 本地存储）

> 全部数字来自**本地已采集数据**的实测推算，未访问任何网站。

## 一、结论速览

| 问题 | 结论 |
|---|---|
| 技术可行性 | ✅ 可行（爬虫已具备状态机、断点续跑、快照、限速） |
| 全量耗时（合规限速 3 s） | **约 10.0 天**（288,206 次请求） |
| 全量存储 | **约 46 GB** 快照 + 0.4 GB 元数据；磁盘可用 365 GB，够用 |
| 是否建议"现在直接全量" | ❌ **不建议**。建议分阶段，理由见 §六 |
| 硬前置条件 | ⚠️ **落盘分桶尚未实现**（当前 253k 文件会全平铺在一个目录） |

## 二、时间测算（基于 108 条实测）

实测：108 个目标 / 378 s，共 **123 次请求**，平均 **1.14 次/目标**（含失败重试）。
成功页平均 212.3 KB（gzip），404 页 1.1 KB。

| 限速设置 | 请求数（全量） | 耗时 |
|---|---|---|
| `--delay 3`（当前默认，≤0.33 req/s） | 288,206 | **240.2 h ≈ 10.0 天** |
| `--delay 2`（0.5 req/s） | 288,206 | 160.1 h ≈ 6.7 天 |
| `--delay 1`（1 req/s） | 288,206 | 80.1 h ≈ 3.3 天 |

## 三、存储测算

| 项 | 全量估算 |
|---|---|
| 页面快照（gzip） | **≈ 46.0 GB** |
| 状态库 SQLite | ≈ 72 MB（253k 行） |
| 暂存层 JSON | ≈ 371 MB（按 1.5 KB/条） |
| 清单/URL | ≈ 24 MB |
| **合计** | **≈ 46.5 GB** |

磁盘：E: 总 931.5 GB，**可用 365.1 GB** → 空间充足。

## 四、工程可行性（逐项）

| 项 | 现状 | 风险 |
|---|---|---|
| 断点续跑 | ✅ SQLite 状态库 + `select_pending` | 无 |
| 幂等 | ✅ 以 ASIN 为主键 upsert | 无 |
| 失败重试 | ✅ 3 次 + 指数退避 | 失败率上升会放大耗时 |
| 限速 | ✅ 全局令牌间隔，与并发无关 | 无 |
| 快照证据 | ✅ gzip + sha256 + final_url | 无 |
| **落盘分桶** | ❌ **未实现**，当前扁平存放 | **253k 文件同目录会拖慢枚举/备份** |
| **长时运行守护** | ❌ 未实现 | 进程中断需人工重启（可续跑，但会空转） |
| 磁盘水位监控 | ❌ 未实现 | 46 GB 增长期间无告警 |

## 五、合规与封禁风险

- 108 条实测 **restricted = 0、validation_page = 0**，说明 3 s 间隔目前未被阻断；
- 但**规模化后的封禁率未知**；一旦升高，`restricted` 会触发重试，实际耗时上涨；
- 按作业 §四任务2，**不得以 IP 轮换/代理池绕过**；被封禁只能如实记录并降低速率。

## 六、是否应该"从全量采集开始"？—— 不建议，理由三条

### 6.1 全量 10 天会吃掉大半个项目周期

作业周期 4 周。10 天连续采集会挤压任务 4–9（合并、补全、血缘，合计约 50 分权重）的时间。

### 6.2 作业**不要求**全量成功

文档 §四任务2 明确"**评分不按实时成功抓取的页面数单独排名**"；
§十 要求"产品清单的互斥最终状态数之和等于 ASIN 总数，**尚未完成者必须显示为未采集**"。
即：**如实标注 `not_collected` 是合规结果**，不是失败。

### 6.3 评论量高度长尾，优先级采集性价比极高（本地实测）

对 7,911,684 条评论按 ASIN 计数（30.4 s 流式完成）：

| 采集范围 | 覆盖评论 | 耗时（3 s 限速） | 存储 |
|---|---|---|---|
| Top 1,000 | 8.2% | ≈ 0.9 h | ≈ 0.18 GB |
| Top 10,000 | **40.8%** | ≈ 9.5 h | ≈ 1.8 GB |
| Top 47,106 | **80.0%** | ≈ 1.9 天 | ≈ 8.5 GB |
| Top 78,432 | 90.0% | ≈ 3.1 天 | ≈ 14 GB |
| 全部 253,059 | 100% | ≈ 10.0 天 | ≈ 46 GB |

**覆盖 80% 评论只需 18.6% 的产品、1.9 天。**

补充分布：评论数中位数 **6**、均值 31.3、最大 957；
评论数 ≥10 的 ASIN 有 104,330 个，≥100 的有 21,150 个。

## 七、建议的执行路线（分阶段，先小后大）

| 阶段 | 规模 | 目的 | 耗时 |
|---|---|---|---|
| **Stage 0** | 1,000（分层抽样） | ①校准分类规则 ②测量规模化封禁率 ③验证分桶与断点 | ≈ 1 h |
| **Stage 1** | Top 10,000（按评论数） | 覆盖 40.8% 评论，支撑任务 4–6 的作品匹配 | ≈ 9.5 h |
| **Stage 2** | Top 47,106 | 覆盖 80%，达到"够用"的作品池 | ≈ 1.9 天 |
| **Stage 3（可选）** | 余下 ~206k | 追求全量覆盖 | +8 天 |

**为什么先 Stage 0**：它用 1 小时就能回答三个关键未知——
规模化封禁率、分类分布是否稳定、分桶方案是否可行，再决定是否投入 10 天。

## 八、三项硬前置——已完成（2026-10 实测）

| 前置 | 实现 | 验证结果 |
|---|---|---|
| **落盘分桶** | `crawler/migrate_pages_to_buckets.py` + 爬虫 `snapshot_path_for()` | 108 个文件全部迁入 **94 个桶**，根目录残留 **0** |
| **守护运行** | `crawler/crawl_supervisor.py` + `scripts\crawl_forever.cmd` | `--max-hours 0` 正常启动退出；pending 读取返回 **252951** |
| **水位监控** | 爬虫 `--min-free-gb`（批间检查）+ 守护同参数 | 当前可用 365.1 GB；低于阈值即刻停 |

> 说明：原计划用 PowerShell 实现守护，但当前会话处于 ConstrainedLanguage 模式，
> `powershell.exe -File` 报 `DotSourceNotSupported`；已改为**纯 Python 实现**，`.cmd` 直接调 Python，
> 脚本不再依赖 PowerShell 语言模式。

| 角度 | 评价 |
