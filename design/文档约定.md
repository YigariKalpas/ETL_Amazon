# 文档与工程约定（默认许可）

> 约定即默认值：新文件按此放置、命名与提交，避免再次出现"文档散落/大文件入库"。

## 一、目录职责

| 目录 | 放什么 | 不放什么 |
|---|---|---|
| `docs/` | 课程材料（作业说明、agent.md、提取文本） | 项目自产设计文档 |
| `design/` | 设计口径、字段分析、落盘规范、文档约定 | 代码 |
| `crawler/` | 采集与解析脚本、采集 README、额度声明 | 原始数据、快照 |
| `environment/` | 环境配置说明（Python/PDI/PostgreSQL/Git 经验） | 运行时产物 |
| `scripts/` | 环境与工具脚本（bootstrap/healthcheck/pg/pdi/git_guard） | 业务逻辑 |
| `etl/` | PDI 资源（`kettle/` 配置、`transformations/` 转换） | 第三方工具本体 |
| `tools/` | 第三方运行时（JDK/PDI/PostgreSQL/便携 Git） | **不入库** |
| `data/` | 原始快照、暂存 JSON、状态库、清单 | **不入库**（用 manifest 记录校验值与恢复方法） |
| `logs/` | 运行日志 | **不入库** |

## 二、编码与换行约定

| 类型 | 编码 | 备注 |
|---|---|---|
| `.md` / `.py` / `.json` | UTF-8（无 BOM） | 中文可直接写 |
| `.ps1` | **UTF-8 with BOM** | PS 5.1 读无 BOM 会按 ANSI 解析，中文必炸 |
| `.cmd` / `.bat` | **纯 ASCII** | cmd.exe 按 OEM 代码页解析，非 ASCII 注释会错位（曾因此产生垃圾文件） |

## 三、命名约定

- 脚本：`snake_case.py`（`crawl_product_pages.py`、`extract_asins.py`）；入口包装 `*.cmd` 与脚本同名。
- 文档：中文名可（`字段分析.md`），但需保证同一目录内不重名。
- 数据文件：`<ASIN>.html.gz`、`<ASIN>.json`；清单 `product_list.csv`、`product_urls.txt`。
- 分支：`main` = 稳定线，`develop` = 开发线。

## 四、提交信息约定（Conventional Commits 简化版）

```
<type>(<scope>): <subject>

type: feat | fix | docs | chore | refactor | test
scope: crawler | etl | db | env | git | design
```

示例：`feat(crawler): product page crawler (bounded concurrency, global rate limit)`

## 五、大文件与不入库规则

- `.gitignore` 已覆盖：`/tools/`、`/data/`、`/logs/`、`movies.txt*`、`*.duckdb`、`*.sqlite`、`*.jar/zip/gz/parquet` 等。
- 提交前跑 `scripts\git_guard.cmd`（钩子在本机不可用，见 `environment/Git经验文档.md`）。
- 大数据的正确提交方式：**manifest（含 sha256）+ 保存位置 + 重跑命令**，而不是数据本体。

## 六、许可与用途

- 本项目为课程作业，按**学术用途**使用；不额外附加开源许可声明。
- 第三方数据（SNAP 评论、Amazon 页面）的使用须遵守其原始条款；
  报告中需说明第三方内容的来源与范围，不提交受限内容的原始副本。
- 不提交任何密码、令牌或凭据；`.gitignore` 已覆盖 `secrets.json`、`.env`。

## 七、文档写作约定

- 每份文档开头一句"目的"，结尾给出"下一步"或"待决定"；
- 事实性结论必须附**可复核证据**（命令输出、sha256、行号、截图路径）；
- 推断与事实分开标注；缺失即写"缺失/NULL + 原因"，不编造；
- 参数、阈值、词表变更必须带版本号（`rule_version`），不得原地覆盖。
