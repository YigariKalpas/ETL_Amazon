## 1. 总原则（贯穿全部规则）

1. **原始值与规范值分离**：任何规范化的值都不得覆盖原始值；两者都有落库位置。
2. **缺失即 NULL + 原因**：查不到就是 NULL，必须带缺失原因，**不得编造**。
3. **不合并优于错合并**：证据不足时保留多个实体并标 `needs_review`，而不是强行合并。
4. **一切判定可追溯**：每条规则有 `rule_id` 与版本，每次运行有 `run_id`，每个字段的取值有候选与选择理由。
5. **幂等**：相同输入 + 相同规则版本重复运行，目标实体与关系数量不变（靠 D1 的确定性键实现）。

## 2. 实体与标识

| 实体 | 主键 | 业务键（UPSERT 用） | 说明 |
|---|---|---|---|
| `ProductEdition` | 代理 ID | **`product_id`（ASIN）** | ASIN 永不删除、永不随合并消失 |
| `Movie` | 代理 `movie_id` | **`identity_hash`** | 合并后取簇内规范种子重算，保证重复运行 ID 稳定 |
| `Person` | 代理 `person_id` | **`identity_hash`** | 同上；姓名相同**不代表**同一人 |
| `Review`（原始） | 代理 ID | **`source_review_id`** | 由源文件哈希 + 记录序号生成 |
| `Review`（逻辑） | 代理 ID | **`logical_review_id`** | 见 §6 |

**D1 细节（建议）**：

- `identity_hash = sha1(规范键材料)`，例如电影取 `normalized_title | release_year | primary_director_norm`。
- 合并**改变簇成员**时，取簇内**最小 ASIN** 重新计算 `identity_hash`，并把旧 hash 记入映射历史；
  这样"合并前后数量与映射历史"可查（文档 §任务4 要求）。
- 不把 ASIN 当 `movie_id`（文档 §三 明确禁止）。

## 3. 归并层次（D2 / D3）

```
L1 作品 (Movie)        同一创作作品，跨 DVD / Blu-ray / 语言 / 字幕 / 地区发行 -> 同一 movie_id
  L2 版本 (Edition)    载体 / 语言 / 字幕 / 地区码 / 剪辑版 / 修复版 -> 各自 edition_id，不合并
L3 合集 (BoxSet)       一个商品含多部作品 -> ProductMovie 多对多 (relation_type=boxset_member)
剧集 (Series)          独立实体，与电影分表、分计数，不与电影混合
```

- **合集评论**：归属 `product_id`，**不复制**给各 `movie_id`（避免制造多条观影评价）。
- **重拍 / 续集 / 同名不同作品**：分别建模，**不合并**，并作为"易混淆未合并"案例提交。
- **导演剪辑版 / 修复版 / 不同片长**：默认归 L2；若同时满足"主创不同"或"情节不同"（判据写入规则），升为独立作品。
- **剧集**：`Series -> Season -> Episode` 三层；剧集评论不计入电影评分。

## 4. 日期语义模型（D4 / D5）

日期一律以**语义四元组**存储，杜绝不同语义日期互相比较：

| 字段 | 取值 |
|---|---|
| `release_date` | 日期（可空） |
| `precision` | `exact` / `day` / `month` / `year` |
| `region` | 地区码（NULL = 首次公开 / 全球） |
| `release_type` | `premiere` / `theatrical` / `festival` |

**硬规则**：

- 只知年份时：`release_year` 有值、`precision=year`、`release_date` **留空**（**禁止**补 1 月 1 日）。
- 商品发售时间走**另一张表** `ProductRelease`（载体 / 地区 / 日期），与作品上映**严格分表**。
- `earliest_review_time` 独立字段，仅作参考；要作"上映不晚于该时间"的**条件性上界**时，
  D5 三条**全部**满足才成立：① 作品映射准确；② 评论非预售；③ 时间可信。
- 启用上界时另存 `inferred_release_bound` + 推断条件 + `confidence`，并把 `status` 标 `inferred`。
- **推断值永不覆盖已核实值**；预售、合集、跨版本评论单独讨论。

## 5. 实体合并（D9 + 评价方法）

**流程**：候选生成 -> 证据验证 -> 三级判定 -> 传递一致性 -> 评价。

1. **候选生成**（仅用于缩小范围，不得作为合并依据）：
   标题规范化（大小写 / 标点 / 冠词 / 罗马数字 / 语言别名）+ 年份桶作为阻塞键。
2. **证据验证**：年份、导演、主演、片长、作品类型、外部 ID；
   **必须 >= 2 项一致，且不得仅靠"标题相似"或仅靠"同年份/缺年份"**（文档 §任务4 明确）。
3. **三级判定**：

   | 档位 | 条件 | 处置 |
   |---|---|---|
   | `auto_merge` | >= 2 项强证据且无冲突 | 自动合并，存证据与置信度 |
   | `needs_review` | 证据部分满足 / 存在冲突 | 保留双实体，进人工复核队列 |
   | `no_merge` | 证据不足或存在反证 | 不合并 |

4. **传递一致性（防链式误合并）**：合并后对每个簇做连通性校验；
   若出现" A~B、B~C 但 A 与 C 证据冲突"，**拒绝自动合并**并标冲突（文档 §任务4 明确要求）。
   采用**层次聚类 + 反证否决**而非裸并查集。
5. **人物消歧**（同规则）：姓名相同 / 缩写相同**都不能直接合并**；
   删中间名、统一大小写**仅用于候选生成**；联合参演作品、职业、年代与已核实外部 ID。
6. **评价集**：电影与人物**各 >= 100 对**人工标注，含应合并与不应合并、覆盖同名作品 / 翻拍 / 合集 / 缩写 / 同名人物；
   **与阈值开发样本分离**，报告 P / R / F1 及分母为零的处理。

## 6. 评论标识与去重（D7 / D8）

- **两级标识**：
  - `source_review_id`：原始记录标识（文件哈希 + 记录序号），**全部保留**；
  - `logical_review_id`：逻辑评论标识；两者用 `ReviewMapping` 关联。
- **候选键**：`(product_id, reviewer_id, review_time, score, md5(review_text))` —— **只生成候选**；
  命中后必须核验差异（如 helpfulness、文本结尾差异），差异写入 `MergeDecision`。
- **不无条件删除**：不同版本上的相似评论**保留**；仅当"映射到同一作品 + 同用户 + 同时间"才视为逻辑重复。
- **质量规则**：`helpful_votes <= total_votes`、`total_votes >= 0`、`score in 1..5`；违规进 `QualityIssue`。
- **D8 评分口径**（默认）：去重、不含合集、分母 = 逻辑评论数；
  报告中必须声明口径，并说明一条评论在多个版本 / 作品间**不会被重复计数**。

## 7. 冲突处理与字段选择（D11）

- 每个字段的每个候选值都落 `FieldAssertion`：`entity_type / entity_id / field_name / raw_value /
  normalized_value / source_record_id / 定位信息 / rule_id / confidence / status`。
- **选择规则**（按序比较，非多数票）：
  1. 来源权威性（已核实外部源 > 商品页面 > 推断）
  2. 字段语义匹配度（发售日 vs 上映日**不同字段**，不比较）
  3. 匹配可靠性（实体匹配置信度）
  4. 精度（`exact` > `month` > `year`）
  5. 采集时间（仅在同级同精度时作裁决，且需说明）
- 最终选择落 `FieldSelection`（`selected_assertion_id` 或候选集合 + 理由 + 规则版本）；
  **未采用候选仍可查看**。多值字段取**并集**，但每个成员都带来源且**角色不混淆**。

## 8. 多值字段与角色（D6 / D10）

- `genres`：定义**受控词表** + 标签映射规则；保留原始标签；多值用关联表（不压成自由文本）。
- `MoviePerson`：`movie_id / person_id / role / billing_order / source`；同一人可在同一作品有多个角色。
- **主演判定（D6）**：仅当来源**显式提供主要演职员**时标 `starring`，并在 `FieldAssertion` 记录
  **覆盖范围**；**不得**把"全部演员"或"任意前三位"当主演（文档 §五 明确）。
- 来源只提供部分演职员时，必须在报告中声明该字段的覆盖边界。

## 9. 规则版本与重算（可复现要求）

- 所有阈值、词表、判据都带 `rule_version`；规则变更**新增版本**而非原地修改。
- 规则变更后，通过 `rule_version` 反查受影响的 `FieldAssertion` / `MergeDecision`，**只重算受影响记录**。
- `ETLRun` 记录批次、工具与规则版本、起止时间、状态、新增 / 更新 / 隔离 / 合并数量。

## 10. 与目标数据模型的对应

本口径可直接映射到文档 §八 建议逻辑模型：`Movie` / `ProductEdition` / `ProductMovie` /
`Reviewer`+`Review` / `ReviewMapping` / `Person`+`PersonAlias` / `MoviePerson` /
`SourceRecord` / `FieldAssertion` / `MergeDecision`+`FieldSelection` / `ETLRun`+`QualityIssue`；
本文新增 `Series/Season/Episode` 与 `ProductRelease` 两张表以承载 D3 与 D4。
