## 五、人工审核方式

### 5.1 生成分层抽样清单

    .venv\Scripts\python.exe crawler\collection_audit.py --sample 30 --out data\staging\audit_sample.csv

按分类分层抽样（本次 27 条），列含义：

| 列 | 用途 |
|---|---|
| asin / 分类 | 被审对象与其机器判定 |
| 标题 / breadcrumb首层 | 人工判断电影/剧集/音乐/其他的主要依据 |
| 媒体格式 / 厂牌 / 时长(分) / 演员数 | 判断是否缺字段、字段是否错位 |
| 快照路径 | 需要看原文时直接打开 |
| **人工结论(待填)** | 由人填写，取值建议：正确 / 分类错 / 字段错 / 无法判断 |

### 5.2 逐条判定规则（照这个填，不用自己发明口径）

| 看什么 | 判为正确 | 判为错误 |
|---|---|---|
| 分类 vs 标题 | 标题是单片电影判 movie；带 Season/Vol./Episode 判 series；CD/DVD 演唱会判 concert 或 music | 例如标题明显是剧集却判 movie |
| 分类 vs 面包屑 | 首层 Movies & TV 且分类属作品类 | 首层是 Books/Toys 却判 movie |
| 时长 | 与标题类型量级相符（电影 80–180 分） | 单集却 400 分（把合辑当单集） |
| 演员数 | 与页面 byline 一致 | 明显只截了前 3 位却当作全部 |
| 缺字段 | 页面本身没有该信息，记客观缺失 | 页面有但没抽到，记解析漏抽 |

### 5.3 通过门槛与处置

- 抽样错误率 = 判错条数 / 抽样条数；**不超过 5% 通过**，写进报告；
- 5%–15%：定位到具体规则（rule_id 在分类 CSV 里）后调规则重跑；
- 超过 15%：暂停下游任务（任务 4/5），先修分类或解析；
- 所有客观缺失不进入错误率分母，单独统计为字段可得性。

### 5.4 三条交叉校验（互相独立，防止单点自证）

| 校验 | 命令 | 期望 |
|---|---|---|
| 面包屑 vs 分类 | 分类 CSV 里 breadcrumb_top 与 classification 对照 | music 31 = CDs & Vinyl 31（本次已核对） |
| 抽样页哈希 | crawler\verify_snapshots.py --asin <抽到的 ASIN> | 两处“与库一致=True” |
| 抽样页重解析 | 重跑 crawler\parse_product_page.py 后对比 staging JSON | 同一条记录字段不变 |

## 六、已知偏差与限制（必须写进报告，不能只报好消息）

| 限制 | 事实 | 影响 |
|---|---|---|
| 覆盖率极低 | 844 / 253,059 = 0.33%，识别作品 643 | 所有占比与分布结论只能代表样本，不能外推全量 |
| 抽样方式 | 每波从剩余池随机抽，种子固定 | 总体近似简单随机，但早采集的页面被排除在后续抽样外 |
| 限流偏差 | 窗口期集中采集，非均匀时间分布 | 若站点对不同品类限流不同，样本可能有品类偏斜（未观测到） |
| 22 条低信息页 | 只有标题，无格式/厂牌/时长 | 已单独计数，不混入覆盖率 |
| 13 条 Various | 演员不可识别 | people 覆盖率被主动压低，属设计取舍 |
| 页面 Release date | 是产品发售日，不是上映日 | 任务 6 上映信息不能直接用它 |
