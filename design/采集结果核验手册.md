## 二、快照完整性（六项检查）

verify_snapshots.py 对每条记录检查：

| # | 检查项 | 失败标记 |
|---|---|---|
| 1 | 状态库登记的快照文件是否存在 | file_missing |
| 2 | gzip 是否可解（损坏检测） | gzip_broken |
| 3 | 解压后内容的 SHA-256 是否等于入库时的 content_sha256 | sha256_mismatch |
| 4 | 解压后字节数是否等于 content_length | length_mismatch |
| 5 | 路径是否符合分桶规则 sha1(ASIN)[:2] | wrong_bucket |
| 6 | 磁盘上是否有状态库未登记的文件 | orphans 计数 |

### 手工核验单条（建议抽查 3–5 条）

    .venv\Scripts\python.exe crawler\verify_snapshots.py --asin B000068TOW

实测输出（库内值与磁盘值并排给出，便于对照）：

    db_content_sha256 = e59940261298674ea17f402a3c1defe1fddd429731822cb607eae0c0be1c3a61
    disk_sha256       = e59940261298674ea17f402a3c1defe1fddd429731822cb607eae0c0be1c3a61  (与库一致=True)
    db_content_length = 788275

**判定标准**：两处“与库一致=True”，且 title 与该 ASIN 的产品一致。

## 三、采集清单与校验值（作业 §十一）

data/crawler/collect_manifest.json 由 verify_snapshots.py --manifest 生成，字段：

| 字段 | 含义 |
|---|---|
| file_count | 快照文件数（= 状态行数） |
| gz_bytes / raw_bytes | 压缩后 / 解压后总字节 |
| digest_of_entries | 对每条 asin+sha256 逐行拼接后的整体摘要，即**清单本身的校验值** |
| entries[] | 每条：asin / status / path / gz_bytes / raw_bytes / sha256 |
| problems[] / orphans[] | 核验发现的问题（本次为空） |

独立复算 digest_of_entries（不信任脚本时）：

    .venv\Scripts\python.exe -c "import json,hashlib;m=json.load(open(r'data\crawler\collect_manifest.json',encoding='utf-8'));s=chr(10).join('%s %s'%(e['asin'],e['sha256']) for e in m['entries']);print(hashlib.sha256(s.encode()).hexdigest())"

与文件里的 digest_of_entries 相同，即清单未过期未篡改。

- 保存位置：data/raw/pages/<sha1(ASIN)[:2]>/<ASIN>.html.gz（分桶，避免单目录 25 万文件）
- 恢复方法：快照是原始响应，可离线重放——见第七节。
