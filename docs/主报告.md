## 1. 数据源与合规

| 项 | 内容 |
|---|---|
| 主数据源 | 公开 Amazon 电影评论数据集（movies.txt，8.69 GB / 71,205,231 行） |
| 补充数据源 | amazon.com 产品页（实时采集，受站点限流约束） |
| 第三方数据源 | IMDb / 豆瓣：未使用（缺数据文件，见 15.1） |

合规（作业 §四 任务2）：

1. 遵守 robots.txt，且失败即中止（取不到就不采）；
2. 全局限速：相邻请求最小间隔 14 秒，并发不提高请求频率；
3. 被限流时只降速、冷却、停止，未做 IP 轮换、代理池、验证码识别、UA 伪造；
4. 验证页作为客观不可访问证据保留，不计入字段覆盖率；
5. 原始页面 gzip + SHA-256 落盘，可复核也可离线重放。

限流实测（关键结论）：站点按请求预算限流，不按瞬时速率。

| 间隔 | 单窗口可用请求 | 之后 |
|---|---|---|
| 3 s | 约 133 次 | 近 100% 验证页 |
| 10 s | 约 190 次 | 近 100% 验证页 |
| 14-18 s | 每波 100 目标 | 健康波 73%-87% 成功率、0 验证页 |

自适应退避：滑动窗口判定（最近 10 次中至少 4 次验证页即暂停 600 秒乘 2 的 n 次方，封顶 1800 秒）；波间冷却 30 分钟起、封顶 4 小时；每波开始前清理验证页并回填待采集。并行采集（2-3 worker）已验证可行，但总产出与单 worker 相当——并发不能突破请求预算。

证据：data/crawler/products.sqlite、collect_manifest.json、logs/wave_*.log、design/Stage0_采集结果与限流观察.md。

## 6. 任务4：同一电影识别

操作性定义：同一创作作品的不同载体/语言/地区/包装共享同一 movie_id，各自保留 edition；重拍、续集、同名不同作品分别建模；合集是 Product 与 Movie 多对多；剧集与电影不混算。

规则（movie_entities/v1）：

| rule_id | 条件 | 判定 |
|---|---|---|
| A-MULTI-FEATURE | 标准标题相同 且（导演一致 或 演员交并比至少 0.6）且 片长差不超过 10 分钟 | 自动合并 |
| A-TITLE-RUNTIME | 标准标题相同 且 片长差不超过 10 分钟 且 载体不同 | 自动合并 |
| A-TITLE-RUNTIME-FUZZY | 标题相似至少 0.90 且 片长差不超过 10 分钟 且 载体不同 | 自动合并 |
| S-SERIES-ROOT | 剧集根标题相同 | 归入同一 series 实体 |
| M-PARTIAL | 标题相似 0.86-1.0 但证据不足 | 人工复核 |
| R-DIRECTOR / R-YEAR-CONFLICT / R-RUNTIME / R-WEAK | 导演冲突、年份冲突、片长差超过 25 分钟、无强特征 | 不合并（留痕） |

结果：1,728 个商品 → **1,718 个 movie 实体**，38 条合并判定（auto / review / reject），**8 组多版本**。

合并实例：

| movie_id | 成员 | 证据 |
|---|---|---|
| M-6302678579 | Candyman (DVD) / Candyman [Blu-ray][1992][UK Import] | 演员交并比 0.667，片长同为 99 分钟 |
| M-B0002V7TJM | Sugar Valentine VHS / DVD | 标题相似 0.914，片长 95/95 |
| M-B0006FFRD4 | Daphne Vol.1 / Vol.1 + Series Box | 标题标准化相同，片长 100/100 |

未合并实例：The Mark of Zorro（1920，Fred Niblo）与 The Mask of Zorro（1998，Martin Campbell）导演明确冲突，判 R-DIRECTOR；Haxan 与 Onibaba 同为 Criterion 包装，片长差 16 分钟，进人工复核而非合并。

复核闭环：review_queue.csv 填 accept/reject 后运行 movie_entities.py --apply-review，决策写回 merge_decision 并标 H-REVIEW-ACCEPT/REJECT。

证据：data/staging/entities/ 下 movie / product_edition / product_movie / merge_decision / review_queue / summary。

## 15. 局限与恢复方法

### 15.1 已知局限

1. 外部数据缺失：任务6 的 verified 上映年份为 0，需 IMDb/豆瓣导出文件；
2. 样本规模：1,886 页 / 253,059 = 0.75%，分布结论只代表样本；限流下全量需 1,200 小时以上，不现实；
3. 年份依赖标题：部分标题带 [1992] 之类年份，只能作证据，不能当上映年；
4. 人物无外部 ID：跨语言与音译合并未做，同名一律保守保留；
5. 评论 text 断言存 sha256 与长度，原文需回查 review 表；
6. PostgreSQL 进程若被外部强杀，重启可能卡在恢复（已复现两次），需 reinit 后重载。

### 15.2 恢复与重跑

    # 采集（可随时中断，状态库保证不重复采）
    .venv\Scripts\python.exe crawler\forever_loop.py --child-max-hours 8 --target-success 5000

    # 全量 ETL
    .venv\Scripts\python.exe crawler\run_pipeline.py

    # 或走 PDI 作业（带失败分支）
    scripts\pdi.cmd kitchen /file:E:\ETL_Amazon\etl\jobs\j_etl_pipeline.kjb

    # 目标层重建与自检
    .venv\Scripts\python.exe crawler\build_target_db.py
    .venv\Scripts\python.exe crawler\verify_target_db.py

    # 清单与校验值
    .venv\Scripts\python.exe crawler\verify_snapshots.py --manifest data\crawler\collect_manifest.json
