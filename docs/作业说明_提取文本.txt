[aa] 数据存储与管理 ETL作业说明
[ac] Amazon电影评论与多源电影信息集成
本作业要求构建一条可重复运行的 ETL 流程：获取 Amazon 历史评论与产品信息，识别电影及人物实体，完成清洗、合并与信息补全，将结果装载到数据库，并保留每个最终字段的来源和处理过程。验收关注数据是否正确、合并是否有依据、结果是否可追溯。
[1] 一 学习目标
[a0] 理解抽取、转换、装载各阶段的输入、输出与职责，并用 ETL 工具组织完整流程。
[a0] 区分电影作品、商品版本、评论和人物，处理异构模式、实体消歧、缺失值与来源冲突。
[a0] 实现全量数据处理、质量检查、失败恢复与字段级数据血缘，形成可复现的数据集成项目。
[1] 二 数据来源和规模
主要数据源为 Stanford SNAP 的 Amazon movie reviews 数据集，下载文件为 movies.txt.gz。官方统计包含 7,911,684 条评论、253,059 个产品和 889,176 个用户，时间范围为 1997 年 8 月至 2012 年 10 月。[1]
评论文件提供产品标识与评论字段，电影名称、类型、导演、演员和上映信息需要从产品页面或其他数据源抽取。产品标识 product/productId 为 ASIN，官方页面用 amazon.com/dp/<ASIN> 示范产品链接；该页面没有提供完整的电影元数据或现成爬虫。[1]
[1] 三 作业范围
必须处理全量评论，并为去重后的全部产品建立采集清单，以获取 253,059 个产品页面为目标。对其中的电影产品执行信息集成。同一产品、同一电影作品和同一人物必须分别具有明确的标识，不得将 ASIN 直接当作合并后的电影 ID。
历史产品页面可能失效、重定向或不可访问。每个产品均须有处理状态；无法取得的页面必须保留原因和证据，不得用空记录冒充成功。若实时采集受到站点限制，应自行调整爬虫程序获取数据。
单人独立完成，周期 4 周；截止时间以课程公告为准。

[1] 四 数据获取与初步清洗
[21] 任务1 全量评论抽取
下载并流式解析 movies.txt.gz，禁止依靠手工复制或仅处理少量样本。记录下载地址、下载时间、文件大小、SHA-256 校验值和解析程序版本。采用分批处理，说明内存、磁盘与运行时间需求。
[a0] 按记录边界及字段前缀解析，妥善处理空字段、编码异常和文本中的分隔符，保留原始文本。
[a0] 为每条原始记录生成稳定的 source_review_id，例如由源文件校验值与记录序号生成；源文件没有提供可直接使用的评论 ID。
[a0] 保留原始记录定位信息及异常记录。提交统计核对：读取记录数 = 有效记录数 + 隔离记录数；清洗与去重导致的数量变化须逐项解释。
[a0] 核对评论总数 7,911,684、不同产品数 253,059 及用户数。若与官方统计不同，先排查下载完整性、空用户值、重复记录和解析规则，不得强行修改结果凑数。
[21] 任务2 产品页面采集
从评论中提取全部不同 ASIN，生成产品采集清单并构造候选链接。使用 Scrapy 或同类工具，在允许访问的范围内采集产品页面，保存原始响应或授权快照。采集器须支持断点续跑、缓存、限速和有上限的重试。[2][3]
[a0] 清单至少记录 ASIN、原始 URL、最终 URL、处理状态、HTTP 状态、尝试次数、获取时间、页面快照位置和内容哈希。
[a0] 状态须区分成功、页面不存在、访问受限、超时、解析失败、未采集等；HTTP 200 的验证页或错误页不得标记为产品页面采集成功。
[a0] 核对返回页面与目标 ASIN 的对应关系，保留重定向与页面模板变化证据；采集时间与评论历史时间分别记录。
[a0] 遵守数据源的访问规则与使用条件，配置 robots.txt 处理、请求间隔和并发上限。遇到访问限制不得以绕过验证、登录或封禁作为完成作业的手段。
[21] 任务3 电影页面筛选
为产品建立电影、非电影、合集、剧集、演唱会或其他、待确认等分类，并给出分类依据。不能仅凭标题含有 DVD 或 Blu-ray 就认定其为电影。对证据不足的产品保留待确认状态；没有电影映射的评论仍需保留。
提交采集状态分布、电影识别数量和字段覆盖率。成功采集率的分母为全部产品数；离线快照、第三方补充与实时采集分别统计，不得混为同一成功指标。

[1] 五 必须抽取的信息与字段定义
以下为最低字段要求。原始值与规范值分开保存；无法获取的字段保留 NULL 和缺失原因。电影类型可多值，导演、主演、演员须通过人物实体关联。
| 字段 | 来源或含义 | 规范化与验收要求 |
| movie_id | 合并后的电影作品 ID | 系统生成稳定 ID；保留 ASIN 到作品的映射。 |
| product_id / edition_id | ASIN 与商品版本标识 | 保留全部原始 ASIN，不随电影合并而删除。 |
| source_review_id | 原始评论记录标识 | 定位源文件和记录；与逻辑评论去重标识区分。 |
| reviewer_id | review/userId | 保留原始用户 ID；不得用显示名替代。 |
| profile_name | review/profileName | 保留原名；不因同名或改名而合并用户。 |
| helpfulness | review/helpfulness | 保存 helpful_votes 与 total_votes；0/0 的比例为 NULL，保留原值。 |
| score | review/score | 转换为数值，按 1 至 5 校验；异常进入隔离或质量记录。 |
| review_time | review/time | 保留 Unix 秒值，并转为 UTC 时间；明确时区。 |
| summary | review/summary | 评论摘要，保留原文和必要的清洗结果。 |
| review_text | review/text | 评论正文，保留原文；不得截断或改变意思。 |
| title / original_title | 电影名与原名 | 保存原名、别名、语言与规范名，支持实体匹配。 |
| release_date / release_year | 电影上映日期或年份 | 标记日期精度、地区与上映类型；区别于商品发售日期。 |
| genres | 电影风格或类型 | 定义受控词表与多值结构；记录标签映射规则。 |
| directors | 导演 | 关联 person_id；支持多位导演。 |
| starring / cast | 主演与演员 | 保留来源角色和排序；主演判定依据须说明。 |
| edition | 版本信息 | 载体、语言、字幕、地区码、剪辑版、发行商及商品发售时间等。 |

“主演”不能无依据地等同于全部演员或任意前三位演员。来源仅提供主要演职员时，应明确覆盖范围。电影版本可以是结构化字段组合，不得只保存一个无法解释的字符串。

[1] 六 电影与人物的实体合并
[21] 任务4 定义并识别同一电影
小组须给出“同一电影”的操作性定义及例外规则。建议将同一创作作品在 DVD、Blu-ray、不同语言、字幕或地区发行中的商品归为同一 movie_id，同时保留各 edition_id。重拍片、续集和同名不同作品分别建模；导演剪辑版、修复版和不同长度版本须明确归并层次与依据。
合集商品可能包含多部电影，采用 Product 与 Movie 的多对多映射；合集评论默认仍归属于商品，不能复制给每部电影而制造多条观影评价。剧集与单集如何处理须另行定义，不得与电影混合计数。
[a0] 先标准化标题、标点、语言别名和明显的商品描述，再用标题、年份、导演或外部 ID 生成候选匹配；必须保留原始标题。
[a0] 结合上映年份、导演、主演、片长及作品类型验证匹配。单独标题相似、单独年份相同或缺失年份均不足以自动合并。
[a0] 设置自动合并、人工复核和不合并的判定规则，保存证据、阈值、置信度及规则版本。
[a0] 检查聚类整体一致性，避免 A 与 B 相似、B 与 C 相似导致互相冲突的 A 与 C 被连带合并。
[a0] 记录合并前后数量及映射历史，支持检查和纠正误合并；展示至少 5 组跨版本合并实例及 5 组易混淆而未合并的实例。
[21] 任务5 人物姓名归一与消歧
为每个人生成 person_id，并保存原始姓名、规范姓名、别名、外部人物 ID 和匹配证据。处理中间名、缩写、音译和不同语言名称时，联合使用参演作品、职业、年代等证据；可优先利用已核实的外部人物标识。
姓名相同不代表同一人；名字缩写相同更不能直接合并。删除中间名或统一大小写仅能用于候选生成。无法确认时保留多个实体及待复核状态，避免误把不同演员合为一人。
[a0] 至少展示 5 组人物别名合并和 5 组同名或近似名不合并的案例，附可核实证据。
[a0] 通过 MoviePerson 关系保存导演、主演、演员等角色；同一人可以在同一作品中具有多个角色。
[a0] 统计电影及人物合并的准确性，评价集与阈值开发样本分离，按第十部分要求报告结果。

[1] 七 缺失信息补全与冲突处理
[21] 任务6 补全上映信息
首先明确上映时间的语义，例如作品首次公开上映日期，或指定地区院线上映日期。电影首映时间、某地区上映时间与 DVD 或 Blu-ray 的商品发售时间分别保存。不同语义的日期不能直接参与择优比较。
可使用 IMDb、豆瓣或其他允许使用的数据源，先通过电影实体匹配确认作品，再抽取日期或年份。IMDb 的公开数据可用于作品标识、上映年份、类型、导演与人物辅助匹配；其公开基础表提供上映年份，不应宣称可从该表获得完整上映日期或全部演员。[4]
[a0] 仅知道年份时保存 release_year 和 precision=year，不得人为补成当年 1 月 1 日。
[a0] 每次补全记录来源、原始值、抽取时间、匹配证据、选择规则和置信度；查不到时保留缺失。
[a0] 最早评论时间仅保存为 earliest_review_time。只有在作品映射准确、评论非预售且时间可信等条件成立时，才可作为“上映不晚于该时间”的条件性上界；不能直接替代真实上映日期。
[a0] 若使用时间推断，另存 inferred_release_bound、推断条件与 confidence，并将 status 标记为 inferred。不得让推断值覆盖已核实的日期；预售、合集和跨版本评论应单独讨论。
[21] 任务7 处理来源冲突
对同一字段建立可复核的选择规则，考虑来源权威性、字段语义、匹配可靠性、日期精度和采集时间。不得简单采用“最后抓到的值”或“多数票”而不说明理由。保留所有候选值及采用、拒绝或待确认状态。
多值字段可取并集，但每个成员都须有来源且不能将角色混淆。标量字段须说明采用哪个候选。无法可靠决策时保留冲突状态，不得编造答案。电影合并后，原始评论、版本属性和来源记录仍可查询。
[21] 任务8 评论清洗与重复识别
声明评论去重的目的与键。例如相同 ASIN、用户、时间、评分和文本可生成候选，但必须核验记录差异。用户在不同版本上的相似评论不能因文本接近而无条件删除。原始记录全部保留，逻辑评论与原始记录使用映射关联。
Helpfulness 的分子不得大于分母，票数不得为负；不满足条件的值记录异常。合并后的电影评分如需计算，须说明是否去重、是否包含合集以及计算分母，避免一条评论在多个版本或作品间重复计数。

[1] 八 ETL架构与目标数据模型
须使用课程ppt中的开源 ETL 工具或具备同等能力的工具组织抽取、转换、装载和质量检查。爬虫与复杂匹配可用 Python 等实现，并由 ETL 作业调用；提交作业定义、依赖关系、参数、执行日志和失败分支。只交若干不相连的脚本不能证明已实现完整 ETL。
[21] 处理层次
原始层保存评论文件、页面快照和第三方数据；暂存层保存结构化抽取值与异常记录；集成层执行电影和人物匹配、补全及冲突决策；目标层保存可查询实体、关系和字段血缘。各层保留源标识与批次标识。
[21] 建议逻辑模型
| 实体或关系 | 关键标识与内容 |
| Movie | movie_id，作品名称、上映信息、类型与状态。 |
| ProductEdition | product_id 即 ASIN，版本、原始页面和商品发售信息。 |
| ProductMovie | product_id、movie_id、关系类型、匹配依据；支持合集。 |
| Reviewer 与 Review | 用户 ID、显示名；原始评论 ID、ASIN、文本、评分和时间。 |
| ReviewMapping | 逻辑评论与原始评论映射；必要时记录评论到作品的映射证据。 |
| Person 与 PersonAlias | person_id、规范名、外部 ID、别名及对应来源。 |
| MoviePerson | movie_id、person_id、角色、署名顺序与来源。 |
| SourceRecord | 源记录 ID、来源地址或文件、快照哈希、原始定位和获取时间。 |
| FieldAssertion | 实体字段候选值、来源、抽取规则、置信度与质量状态。 |
| MergeDecision 与 FieldSelection | 实体合并证据；最终字段所采用的候选集合和选择理由。 |
| ETLRun 与 QualityIssue | 批次、工具和规则版本、起止时间、状态、异常与重处理结果。 |

可采用不同表名或关系型数据库、文档数据库等实现，但须表达同样的实体边界与关系。日期地区、多值类型及多来源支持不得压缩成无法查询的自由文本。提交 ER 图、建表或建模脚本、键与约束、索引及字段字典。
[21] 可重复运行与恢复
相同输入与规则版本再次运行，不得生成重复目标实体或重复关系；人为中断后须能从已完成批次恢复。记录新增、更新、隔离和合并数量；规则变化时保留决策版本，说明如何重新计算受影响记录。

[1] 九 字段级数据血缘
[21] 任务9 保存来源与采用过程
血缘必须回答：某部电影的某个字段是什么，从哪些原始记录抽取，经哪些清洗、匹配或推断操作形成，最终为何采用这一值。只有 ETL 流程图、任务级日志或电影到 URL 的简单映射，不能满足字段级要求。
[a0] 原始证据可定位：网页 URL 与快照哈希，或数据文件版本与记录序号、行号或其他稳定定位；同时记录获取时间。
[a0] 候选值可追踪：entity_type、entity_id、field_name、raw_value、normalized_value、source_record_id、字段定位信息和抽取规则版本。
[a0] 处理过程可重建：候选或中间结果之间的父子关系、操作类型、rule_id、run_id、时间及必要的置信度。
[a0] 最终选择可解释：selected_assertion_id 或候选集合、决策理由与版本；未采用候选仍可查看。
[a0] 多源与多值可表达：一字段可依赖多个输入；演员列表的每个成员与其角色分别具有证据。推断值须列出全部依赖评论及算法版本。

[1] 十 数据质量与验收要求
[21] 数量与完整性
[a0] 提交全量评论及产品数量核对；产品清单的互斥最终状态数之和等于不同 ASIN 总数，尚未完成者必须显示为未采集或待处理。
[a0] 报告有效、异常及重复评论数量，电影产品、非电影产品、待确认产品数量，以及合并前后作品和人物数量。
[a0] 分字段报告覆盖率。电影信息以已识别作品为分母，另报告全部产品的识别覆盖率；缺失、推断和已核实结果分别统计。
[a0] 检查主键唯一性、外键有效性和映射一致性。每个非空最终字段必须能追溯到原始来源或明确标记的人工修订记录。
[21] 实体匹配评价
电影与人物各建立至少 100 对人工标注的独立评价样本，分别包含应合并与不应合并案例，并覆盖同名作品、翻拍、合集、名字缩写和同名人物等难例。说明抽样方式、标注依据与分歧处理；规则开发与评价样本分开。
报告自动合并的 Precision、Recall、F1，并给出误合并和漏合并实例。Precision = 正确预测为同一实体的对数 / 预测为同一实体的对数；Recall = 正确预测为同一实体的对数 / 标注为同一实体的对数；F1 为两者的调和平均。说明分母为零时的处理。
人工复核覆盖率和待确认率单独报告。此处指标评价所构造的样本，不能直接宣称代表全量准确率；额外抽查实际合并簇，检查传递合并错误。

[a0] 提供固定的验收样本和原始证据，可离线完成端到端运行；样本须含跨版本合并、人物别名、非电影、合集、缺失日期、来源冲突及采集失败。
[a0] 同一输入运行两次，核对目标记录数与关系数，证明装载幂等；中断后恢复，证明不会漏处理或重复装载。
[a0] 证明规则或来源改变后，可以定位受影响字段并重新执行相应步骤。
[21] 结果查询与现场展示
至少提供 5 个可执行查询：查询作品的所有商品版本；查询某导演的作品及来源；查询缺失与推断上映信息；查询字段冲突和选择理由；按产品或作品统计评论数量与评分。最后一项须解释合集、重复评论与版本合并的口径。
现场展示建议 10 至 15 分钟。每位成员须能解释所负责的规则、数据模型和错误案例；教师可随机抽取字段检查血缘，并要求重新执行小批次。
