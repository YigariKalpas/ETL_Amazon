# 数据库选型分析（P0-3）

> 目的：为作业的**目标层（可查询实体/关系/字段血缘）**选定数据库，并给出可落地的获取方式。
> 结论均基于作业文档要求 + 本机实测。

## 一、约束条件（来自作业文档）

| 要求 | 出处 | 对选型的含义 |
|---|---|---|
| 提交 ER 图、**建表或建模脚本、键与约束、索引及字段字典** | §八 | 必须支持 PK / FK / UNIQUE / CHECK / 索引 |
| 检查**主键唯一性、外键有效性**和映射一致性 | §十 | FK 需**被强制**，而非仅声明 |
| **多值类型**（genres、cast）与日期地区"不得压缩成无法查询的自由文本" | §八 | 需要数组 / JSONB / 规范化多值表 |
| 5 个结果查询 + 4 类血缘查询（多表 join、候选集合） | §九/§十 | 需要良好的 join / 窗口函数 / 聚合性能 |
| 全量：7,911,684 条评论、253,059 个产品；血缘候选表可达千万级 | §二/§九 | 需要能承受千万级行的引擎 |
| 装载**幂等**、可恢复、批次与规则版本 | §八/§十 | 需要 UPSERT / 事务 / 约束帮助去重 |
| 允许"关系型数据库、文档数据库等" | §八 | 不限定关系型，但须表达同样的实体边界 |

## 二、本机沙箱实测（决定性边界）

| 实测项 | 结果 | 影响 |
|---|---|---|
| 绑定/监听/连接 `127.0.0.1:5432` | ✅ 成功 | **服务型**数据库（PostgreSQL/MySQL）可行 |
| 写入 `E:\ETL_Amazon` 之外 | ❌ Permission denied | 数据库**数据目录必须放在项目内** |
| Docker | ❌ 未安装 | 不能走容器方案 |
| 磁盘可用 | ✅ 约 391 GB | 容量充足 |

## 三、候选方案对比

| 维度 | **PostgreSQL 17（便携版）** | **DuckDB** | **SQLite** | MySQL / MariaDB |
|---|---|---|---|---|
| 形态 | 服务进程（本机 127.0.0.1） | **进程内**（库文件） | **进程内**（单文件库） | 服务进程 |
| 约束强制 | ✅ 全（PK/FK/UNIQUE/CHECK） | ✅ 全（**已核实**，含 FK；FK 自动建 ART 索引） | ⚠️ 部分（需 `STRICT` 表才有强类型；FK 需 `PRAGMA foreign_keys=ON`） | ✅ 全（InnoDB） |
| 多值字段 | ✅ 数组 + JSONB + 规范化表 | ✅ LIST / STRUCT / JSON | ❌ 无原生数组，靠子表 | ⚠️ JSON 较弱 |
| 千万级血缘表 | ✅ 强 | ✅ **很强**（列存，聚合/join 最快） | ⚠️ 明显偏慢 | ✅ 中上 |
| 并发写 | ✅ MVCC 多写者 | ⚠️ **单写者**（同进程/单文件） | ⚠️ 单写者（WAL 下读写可并发） | ✅ |
| 相对 PDI 的 JDBC | ✅ 官方 42.x，最成熟 | ⚠️ 有 JDBC（org.duckdb），但受单写者限制 | ✅ xerial sqlite-jdbc | ✅ Connector/J |
| 安装/运维成本 | ⚠️ 中（需 initdb + 常驻进程；但可免管理员、免服务） | ✅ **极低**（pip 一条命令） | ✅ **零**（Python 内置） | ⚠️ 中 |
| 提交与复现 | ⚠️ 数据目录（可打包） | ✅ **单文件**（.duckdb） | ✅ **单文件** | ⚠️ 数据目录 |
| 许可 | PostgreSQL License（宽松） | MIT | Public Domain | GPL/商业双许可 |
| 本题适配度 | ★★★★★ | ★★★★☆ | ★★☆☆☆ | ★★☆☆☆ |

**说明**
- DuckDB 的"约束会被过于急切地求值"警告来自官方文档：索引限制可能导致 `violates primary key/unique constraint` 误报，**发生在更新主键列**的场景。纯 INSERT 的装载流程不受影响，但需注意。
- SQLite 的 Python 内置版本为 **3.50.4**，可直接开工（零安装），适合承担**爬虫状态队列**与**固定验收样本**。
- MySQL/MariaDB 对本项目**没有相对优势**，却多一套运维，故不推荐。

## 四、获取方式（具体）

### 4.1 PostgreSQL 17 —— 免安装便携版（推荐）

```
# 1) 下载 “binaries only” 归档（无需管理员、不注册 Windows 服务）
#    https://www.enterprisedb.com/download-postgresql-binaries
#    选 “Binaries from installer Version 17.11”（或 18.6）
# 2) 解压到无空格路径
#    -> E:\ETL_Amazon\tools\pgsql
# 3) 初始化数据目录（必须放在项目内）
tools\pgsql\bin\initdb.exe -D E:\ETL_Amazon\data\pgdata -U etl -E UTF8 --locale=C
# 4) 启动（仅监听本机）
tools\pgsql\bin\pg_ctl.exe -D E:\ETL_Amazon\data\pgdata ^
    -l E:\ETL_Amazon\logs\pg.log ^
    -o "-p 5432 -c listen_addresses=127.0.0.1" start
# 5) 建库
tools\pgsql\bin\createdb.exe -h 127.0.0.1 -p 5432 -U etl etl_amazon
# 6) JDBC 驱动（PDI 通过 JDBC 访问）
#    https://jdbc.postgresql.org/download/  -> postgresql-42.7.x.jar
#    放入 tools\pdi-ce-9.4.0.0-343\data-integration\lib\
```

- 另有官方交互式安装器（含 pgAdmin/StackBuilder）：https://www.postgresql.org/download/windows/ —— 需管理员且会注册服务，**本沙箱不推荐**。
- 文本协议端口已验证可绑定；数据目录务必在 `E:\ETL_Amazon` 内。

### 4.2 DuckDB —— 进程内分析引擎（建议同时具备）

```cmd
rem Python 包（最简，推荐）
.venv\Scripts\python.exe -m pip install duckdb

rem 可选：独立 CLI
rem https://github.com/duckdb/duckdb/releases  -> duckdb_cli-windows-amd64.zip

rem 可选：PDI 所需 JDBC 驱动（Maven Central）
rem org.duckdb:duckdb_jdbc:<version>  -> 放入 data-integration\lib\
```

### 4.3 SQLite —— 零安装（爬虫状态 + 验收样本）

```cmd
rem Python 已内置 sqlite3 3.50.4，无需安装
.venv\Scripts\python.exe -c "import sqlite3; print(sqlite3.sqlite_version)"

rem 可选：命令行工具
rem https://www.sqlite.org/download.html -> sqlite-tools-win-x64-*.zip
rem 可选：JDBC -> org.xerial:sqlite-jdbc
```

### 4.4 MySQL / MariaDB —— 备选

```
# MySQL Windows ZIP Archive（免安装）: https://dev.mysql.com/downloads/mysql/
#   mysqld --initialize-insecure --datadir=E:\ETL_Amazon\data\mysql
#   mysqld --datadir=... --port=3306
# MariaDB ZIP: https://mariadb.org/download/
# JDBC: mysql-connector-j / mariadb-java-client -> data-integration\lib\
```

## 五、推荐组合

| 角色 | 选型 | 理由 |
|---|---|---|
| **目标层（主库）** | **PostgreSQL 17 便携版** | 约束/FK 强制、数组与 JSONB 表达多值、JDBC 最成熟，最贴合文档对"关系型 + 键与约束 + 字段字典"的预期 |
| **校验/分析引擎** | **DuckDB**（pip） | 直接扫描大文件与血缘表做统计核对，列存最快；零运维 |
| **爬虫状态 + 验收样本** | **SQLite**（内置） | 断点续跑状态表、固定验收样本，零安装、单文件易提交 |

**风险与待验证**
1. PostgreSQL 服务进程需在沙箱内**持续存活**（`pg_ctl start` 分离进程 + DSH 后台任务）。端口绑定已验证可行，但"常驻"需实测；若受限则退回 **DuckDB 为主库**。
2. 驱动 jar 放入 `data-integration\lib\` 后需重启 Spoon/Pan 才生效。
3. 数据目录、日志均须落在项目内；`.gitignore` 需补 `/data/`、`/logs/`。
